# Homeplate Workouts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Log a workout (cycling first) by hand, with the app estimating calories when the user has no number of their own, and have the day's calories shown net of what was burned.

**Architecture:** A `workouts` table and a small router beside Today. Estimation is a pure function (activity, intensity, minutes, body weight). Today's hero switches from eaten to net calories and lists workouts with the day's entries. A per-user setting says what share of workout calories counts.

**Tech Stack:** Unchanged.

**Spec:** `docs/superpowers/specs/2026-11-09-workouts.md`.

## Global Constraints

- No new dependency, no inline `<script>` or `style=""`, one stylesheet using the existing tokens and components; all state changes are POST; all SQL parameterised and filtered on the signed-in user's id; a user can only read or change their own workouts.
- Activities, in this order: `cycling`, `running`, `walking`, `strength`, `swimming`, `other`. Intensities: `easy`, `moderate`, `hard`.
- Estimate formula: `kcal = round((MET - 1) * weight_kg * minutes / 60)`, the calories burned above resting. MET table:

  | activity | easy | moderate | hard |
  |---|---|---|---|
  | cycling | 4.0 | 8.0 | 10.0 |
  | running | 7.0 | 9.8 | 11.5 |
  | walking | 3.0 | 3.8 | 5.0 |
  | strength | 3.5 | 5.0 | 6.0 |
  | swimming | 6.0 | 8.0 | 10.0 |
  | other | 3.0 | 5.0 | 7.0 |

- Body weight for the estimate is the user's most recent logged weight (pounds, converted with 0.45359237); with none logged, 170 lb, and the form says "Log your weight for a better estimate."
- Limits: minutes 1 to 1440; calories blank or 0 to 20000. A calories value typed by the user is stored as given with `source = 'entered'`; a blank one is estimated and stored with `source = 'estimated'`.
- Counted burn = `burned * workout_pct // 100`, with `workout_pct` 0 to 100, default 100. Net = eaten minus counted burn (it may be negative).
- Calorie numbers never use the danger or warning colour. Workout calories are shown as "burned", never as a reward or a debt.
- Schema changes to an existing table go through `db.add_column_if_missing(con, table, column, ddl)`, created in this plan if it does not exist yet, with exactly this body:

```python
def add_column_if_missing(con, table: str, column: str, ddl: str) -> None:
    if column not in [r["name"] for r in con.execute(f"PRAGMA table_info({table})")]:
        con.execute(f"ALTER TABLE {table} ADD COLUMN {column} {ddl}")
```

## Review Focus

1. No weight logged, and a workout so long or hard that the estimate is large: sensible number, no crash, the hint about logging weight shown. Test in Task 1.
2. Minutes or calories that are blank, zero, negative, non-numeric or absurd (`1e300`): a message, nothing saved, no 500. Test in Task 1.
3. Another user's workout cannot be read or deleted: 404. Test in Task 1.
4. Net calories below zero (burned more than eaten) and exactly at target: the hero reads correctly, with no negative percentage and no warning colour. Test in Task 2.
5. `workout_pct` of 0 and of 100, and a database created before this plan (column missing): correct maths, column added on connect. Test in Task 2.

### Task 1: Workouts: estimate, storage, logging

**Files:**
- Create: `app/workouts.py`, `app/templates/_workout.html`, `app/templates/_workout_calories.html`, `tests/test_workouts.py`
- Modify: `app/db.py`, `app/main.py`, `app/today.py` (`_page` loads today's workouts), `app/templates/today.html`, `app/static/app.css`

**Interfaces:**
- Produces:
  - Table `workouts(id INTEGER PRIMARY KEY AUTOINCREMENT, user_id TEXT NOT NULL REFERENCES users(mealie_user_id), day TEXT NOT NULL, activity TEXT NOT NULL, minutes INTEGER NOT NULL, intensity TEXT NOT NULL, calories INTEGER NOT NULL, source TEXT NOT NULL CHECK (source IN ('entered','estimated')), note TEXT, created_at TEXT NOT NULL)`.
  - `workouts.estimate(activity: str, intensity: str, minutes: int, weight_lbs: float | None) -> int` (pure).
  - `workouts.latest_weight(con, user_id) -> float | None`.
  - `POST /workouts`: fields `activity`, `intensity`, `minutes`, `calories` (optional), `note` (optional, at most 200 characters); dated `today.local_today()`; redirects 303 to `/` on success; re-renders Today with a message and the workout form open on invalid input.
  - `POST /workouts/estimate` (htmx): same fields; returns the `_workout_calories.html` fragment, a calories input prefilled with the estimate and a hint "Estimated from N minutes at <intensity> effort and <W> lb. Change it if you know better."; invalid input returns the fragment with an empty value and a short message.
  - `POST /workouts/{id}/delete`: owner only, 404 otherwise; redirects 303 to `/`.
  - Today: an "Add workout" `details.more` card after "Add food": activity select (cycling first), minutes (`inputmode="numeric"`), intensity radios (moderate preselected), an "Estimate" secondary button wired to `/workouts/estimate`, the calories field labelled "Calories burned (leave blank to estimate)", note, and a primary "Log workout" button. Workouts appear in "Logged today" after food entries, each as "Cycling", a chip "Workout", "90 min · 600 kcal burned" (with "estimated" when `source` is `estimated`), and Remove inside the same disclosure pattern as entries.
  - `_page` context gains `workouts` (today's rows) and `burned` (their calorie sum).

### Task 2: Net calories on Today, and the share-of-calories setting

**Files:**
- Modify: `app/stats.py`, `app/today.py`, `app/templates/today.html`, `app/me.py`, `app/templates/me.html`, `app/db.py`, `tests/test_today.py`, `tests/test_me.py`, `tests/test_stats.py`, `app/static/app.css`

**Interfaces:**
- Consumes: Task 1's `burned`.
- Produces:
  - `users.workout_pct INTEGER NOT NULL DEFAULT 100`, added with `db.add_column_if_missing`.
  - `stats.net_calories(eaten: int, burned: int, pct: int) -> tuple[int, int]` returning `(counted_burn, net)`.
  - Today hero: the ring and "N left" / "N over" use net against the target (percentage still clamped 0 to 100; a negative net shows 0% and "N left" with N = target minus net); the centre number is net; below it one line "1,840 eaten · 600 burned" when anything was burned today (showing the counted amount, with "of 800" appended when `workout_pct` is under 100); with nothing burned the hero is exactly as before. Without a calorie target: the total alone as before, plus the same eaten and burned line when anything was burned.
  - The ring's accessible label states net, eaten and burned.
  - Me settings, in the Goals group: "Share of workout calories to count (%)", whole number 0 to 100, with the hint "Estimates run high. Lower this if your weight stops moving." Validated all-or-nothing with the other settings.
