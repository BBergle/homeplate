# Chat only: Homeplate becomes a chat window for Mealie

**Decided by the owner on 2026-11-10:** "homeplate was just a chat window for mealie, and I do everything else in mealie". Asked whether to keep the calorie diary, weight, workouts and streak, the answer was "chat only": remove Today and Me; no tracking.

**Goal:** After sign-in, Homeplate is the Ask chat plus a small Settings page. Everything Mealie already does, and everything Homeplate tracked on its own, is gone from the app.

**Spec this changes:** `docs/superpowers/specs/2026-11-09-assistant.md` (the controller updates it and `docs/HANDOFF.md`; do not edit those two).

## What stays

- Sign-in and sign-out with Mealie accounts, sessions, the same-origin guard and body limit.
- The Ask tab exactly as it is: chat, web search, sources, recipe cards with Add, look-ups, New chat.
- Each person's AI key and model (`POST /settings/ai`), now on a Settings page.
- Invites, account requests and the admin page (`/invite`, `/join/...`, `/request...`, `/admin...`): unchanged. They are how people get an account.
- The database file and everything in it. **Do not drop or alter any table or column, do not delete any row, and do not delete any file under `DATA_DIR`.** `db.SCHEMA` and the `add_column_if_missing` calls stay exactly as they are, so old diary, weight, workout and photo data remains readable if the owner changes their mind.

## What goes

- Pages and routes: Today (`/`, `/entries...`, `/weight`, `/recipes/search`), workouts, the Me page's goal, streak, achievements, savings, weight chart, cooked list and goal settings (`/me`, `POST /settings`), the recipe page and photo galleries (`/r/...`, `/photos/...`), the Order placeholder (`/order`).
- Modules: `app/today.py`, `app/workouts.py`, `app/stats.py`, `app/gallery.py`, `app/photos.py`, `app/me.py`.
- Templates: `today.html`, `_entry.html`, `_workout.html`, `_workout_calories.html`, `_recipe_results.html`, `recipe.html`, `soon.html`, `me.html`, and `notfound.html` if nothing else renders it.
- Tests for the removed things: `tests/test_today.py`, `test_workouts.py`, `test_stats.py`, `test_gallery.py`, `test_recipe.py`, `test_me.py`, and the parts of `test_ui.py`, `test_auth.py` and others that exercise removed pages.
- Functions in `app/mealie.py` that nothing calls any more (check each with grep: `recipe_image`, `planned_today`, `leading_number` are candidates; `me`, `search_recipes`, `recipe`, `test_scrape`, `import_url` and the invite and account functions stay).
- CSS rules in `app/static/app.css` that only the removed pages used. For each rule you delete, grep the remaining templates for its class first; when unsure, leave it.
- The `next` deep link on sign-in (`auth.safe_next`, the hidden field in `login.html`, `?next=` in `drop_session`): it only ever allowed `/r/...`, which no longer exists. After sign-in everyone lands on the chat.

## What changes

1. **Home is the chat.** `GET /` answers 303 to `/ask`. Sign-in redirects to `/` as before.
2. **Tab bar:** two tabs, in this order: `("/ask", "ask", "Ask")` and `("/settings", "me", "Settings")` (the existing person icon). The Settings tab is current on `/settings...`, `/invite`, `/admin...`; Ask otherwise.
3. **Settings page:** new `app/settings.py` and `app/templates/settings.html`. `GET /settings` shows the page head "Settings", the AI assistant section (the same fields, copy, messages and behaviour as today's section in `me.html`, but as a plain always-visible `<section class="card" id="ai">`, not a collapsed `<details>`), then the account buttons that are on Me today (Admin with its pending-request count for admins, Invite someone, Sign out). Move `POST /settings/ai` (`save_ai`) from `app/ask.py` into `app/settings.py` unchanged in behaviour; a refusal or warning re-renders the Settings page with the message, success redirects to `/settings`. The `?ai=1` flag is no longer needed: remove it. `ask.html`'s "Open Settings" links to `/settings#ai`.
4. **Time helpers:** `ask.py` needs today's date in the app's timezone and `access.py` needs the timezone. Move `local_today()` and the timezone helper (as `local_tz()`) into `app/auth.py` and use them from there.
5. **Cards link to Mealie.** A card that has been added shows "Added to your recipes." and, when `MEALIE_PUBLIC_URL` is set and the person's group is known, a link `Open in Mealie` to `<MEALIE_PUBLIC_URL>/g/<group slug>/r/<recipe slug>` with `target="_blank" rel="noopener noreferrer"`. At Add time, after a successful import, look up the group slug with `mealie.me(token).get("groupSlug")` and store `g/<group>/r/<slug>` (each part URL-quoted) in the card's `result`; if that look-up fails for any reason the card is still `done`, with an empty `result` and no link. A failure there must never undo or repeat the import.
6. **System prompt:** the opening sentence becomes "You are the cooking assistant inside Homeplate, a chat window for the person's Mealie recipe manager." The rest of the prompt is unchanged.
7. **README:** describe what Homeplate is now (a chat assistant for Mealie: find recipes on the web and add them with a tap, ask about saved recipes), keep the environment variable table accurate (`MEALIE_PUBLIC_URL` is now what the "Open in Mealie" links use; `TZ` sets the date the assistant is told), keep the `SECRET_KEY` notes, and remove sections about removed features. Plain short sentences, no em dashes.
8. **`scripts/shots.sh`:** default paths become `/ask /settings /login`.
9. `requirements.txt` is unchanged (keep `pillow-heif`: photo input is coming).

## Tests

- `GET /` signed in answers 303 to `/ask`; signed out, `/ask` and `/settings` send the person to `/login`.
- Each removed page answers 404 signed in: `/me`, `/order`, `/r/x`, `/weight` (GET), `/recipes/search`, `/photos/1`.
- The tab bar has exactly two links, with the right one current on `/ask`, `/settings`, `/invite`, `/admin`.
- Settings page: the AI section is visible without any query flag; admins see the Admin button with the pending count, others do not; Invite and Sign out are present. All existing AI-settings tests keep their assertions, pointed at the new page and redirect target.
- Sign-in lands on `/` and then `/ask`; a posted `next` value is ignored.
- Card Add: `result` is `g/<group>/r/<slug>` and the card shows `href="<MEALIE_PUBLIC_URL>/g/<group>/r/<slug>"`; with `MEALIE_PUBLIC_URL` unset there is no link; when the group look-up fails (500) the card is `done` with no link and Mealie's import was called once.
- A database made by the previous version still opens and its old tables and rows are untouched: create the tables with a few rows (an entry, a weight, a workout, a photo row), open the app, sign in, and assert the rows are still there.
- Everything else that tests kept behaviour (chat, cards, look-ups, key encryption, invites, requests, admin, same-origin guard, body limit) passes unchanged apart from URL updates.

## Rules

- Branch `chat-only`. `.venv/bin/pytest -q` passes at every commit.
- This is mostly deletion. Do not rewrite kept code beyond what the removals force. No new features, no new dependencies.
- New page elements use their own class names (`settings-*`); do not restyle existing classes.
- The AI key is never rendered or logged. Model text is always escaped.
- Commit in a few logical steps (for example: move helpers and Settings; remove pages and tests; cards link to Mealie; README and scripts). Do not push.
