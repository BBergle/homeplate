# Homeplate Step 1 (Core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A container you can sign in to with a Mealie account, log cooked meals (with photo), other food and weight, and see calories, weekly streak, achievements and savings, with tests and image builds running on GitHub.

**Architecture:** One FastAPI app rendering Jinja2 templates with htmx, SQLite through stdlib `sqlite3`, photos on disk under `/data`. Mealie is called over HTTP with the signed-in user's token. Stats are pure functions over entry rows; nothing derived is stored.

**Tech Stack:** Python 3.12, FastAPI, Jinja2, htmx (vendored file), httpx, Pillow, python-multipart, cryptography (Fernet), pytest. GitHub Actions, GHCR.

**Spec:** `docs/superpowers/specs/2026-11-09-homeplate-design.md`. This plan covers build step 1 only. Steps 2 to 5 (sharing and invites, AI, Kroger, Unraid) each get their own plan when reached.

## Global Constraints

- No JS build step, no ORM, no chart library, no new dependency beyond the stack above.
- Env vars: `MEALIE_URL`, `MEALIE_PUBLIC_URL`, `SECRET_KEY`, `BASE_URL`, `TZ`, `DATA_DIR` (default `/data`).
- "Today" and week boundaries use `TZ` via `zoneinfo`; weeks run Monday to Sunday.
- Every route except `/login`, `/healthz` and `/static/*` requires a session; a missing or expired one redirects to `/login`.
- All state changes are POST. Session cookie `sid`: `HttpOnly`, `SameSite=Lax`, `Secure` when `BASE_URL` is https.
- A user can only read or change their own entries, photos and weights; anything else is 404.
- Phone-first: bottom tab bar (Today, Me, Order, Ask; the last two are "coming soon" pages in this step), touch targets at least 44px, no horizontal scroll at 375px.
- Defaults for a new user: `weekly_goal=3`, `delivery_cost=25`, `home_meal_cost=6`, other targets empty.
- Commit after each task; push to `main` on GitHub (`BBergle/homeplate`, private).

## Review Focus

1. Mealie unreachable or returning 5xx: every page shows a plain "Can't reach Mealie" message, never a stack trace. Test in Task 3.
2. Mealie token expired mid-session (Mealie returns 401): the session is deleted and the user lands on `/login`. Test in Task 3.
3. Upload that is not an image, or is over 15 MB: rejected with a message, nothing written to disk, the entry is still saved. Test in Task 4.
4. User A posting to delete or fetching user B's entry or photo: 404. Test in Task 4.
5. Recipe nutrition that is `None`, `""`, `"about 300 kcal"` or `"312.5"`: parses to `None`, `None`, `300`, `312`. Test in Task 3.

### Task 2: Database and stats

**Files:**
- Create: `app/db.py`, `app/stats.py`, `tests/test_stats.py`

**Interfaces:**
- Produces:
  - `db.connect() -> sqlite3.Connection` (row factory `sqlite3.Row`, foreign keys on, creates schema if missing at `$DATA_DIR/homeplate.db`).
  - Tables as in the spec, except `entries` uses `day TEXT` (local `YYYY-MM-DD`) plus `created_at` instead of `eaten_at`. The `shares` table is not created in this step.
  - `stats.week_totals(days: list[date], today: date) -> list[int]`: count of days-entries per Monday-to-Sunday week, oldest first, from the week of the earliest entry through the week containing `today`; `[0]` if no entries.
  - `stats.streak(totals: list[int], goal: int) -> int`
  - `stats.longest_run(totals: list[int], goal: int) -> int` (longest run of consecutive weeks with total >= goal)
  - `stats.achievements(home_meals: int, distinct_recipes: int, longest: int) -> list[tuple[str, bool]]` with names, in order: `"First cook"` (>=1), `"10 meals"`, `"50 meals"`, `"4-week streak"` (longest >= 4), `"5 different recipes"`.
  - `stats.savings(home_meals: int, delivery_cost: float, home_meal_cost: float) -> float` = `home_meals * (delivery_cost - home_meal_cost)`.

- [ ] **Step 1:** Write `tests/test_stats.py` with these assertions (goal 3 unless stated):
  - `streak([3, 3, 3], 3) == 3`
  - `streak([3, 0, 4, 3], 3) == 3` (missed week repaired by goal + 1 the next week)
  - `streak([3, 0, 3, 3], 3) == 2` (not repaired)
  - `streak([3, 0, 0, 4], 3) == 1` (two misses in a row reset)
  - `streak([3, 3, 1], 3) == 2` (current week in progress is not a miss)
  - `streak([3, 0, 1], 3) == 1` (last week missed, still repairable this week)
  - `streak([0], 3) == 0`
  - `longest_run([3, 3, 0, 3, 3, 3, 3, 0], 3) == 4`
  - `week_totals([date(2026,11,2), date(2026,11,8), date(2026,11,9)], date(2026,11,9)) == [2, 1]` (Mon 2 Nov and Sun 8 Nov share a week)
  - `week_totals([], date(2026,11,9)) == [0]`
  - `savings(10, 25, 6) == 190`
  - `achievements(1, 1, 0)` has only `"First cook"` earned.
- [ ] **Step 2:** `pytest tests/test_stats.py -q` fails on import.
- [ ] **Step 3:** Implement `app/stats.py`. `streak` is exactly:

```python
def streak(totals: list[int], goal: int) -> int:
    n, last = 0, len(totals) - 1
    for i in range(last, -1, -1):
        if totals[i] >= goal:
            n += 1
        elif i == last:                       # current week still in progress
            continue
        elif i + 1 == last or totals[i + 1] >= goal + 1:   # repairable or repaired
            continue
        else:
            break
    return n
```

### Task 3: Mealie client and sign-in

**Files:**
- Create: `app/mealie.py`, `app/auth.py`, `app/templates/base.html`, `app/templates/login.html`, `app/templates/error.html`, `app/static/app.css`, `app/static/htmx.min.js`, `tests/test_auth.py`, `tests/conftest.py`
- Modify: `app/main.py`

**Interfaces:**
- Consumes: `db.connect()`.
- Produces:
  - `mealie.MealieError` (unreachable or 5xx) and `mealie.MealieAuthError` (401).
  - `mealie.login(username: str, password: str) -> str` (access token; raises `MealieAuthError` on 401 and 423).
  - `mealie.refresh(token: str) -> str`
  - `mealie.me(token: str) -> dict` (`id`, `fullName`, `admin`)
  - `mealie.search_recipes(token: str, q: str) -> list[dict]` (`id`, `slug`, `name`)
  - `mealie.recipe(token: str, slug_or_id: str) -> dict`
  - `mealie.planned_today(token: str) -> list[dict]` (recipes from today's meal plan entries; entries without a recipe are skipped)
  - `mealie.leading_number(value: str | None) -> int | None`
  - `mealie.client: httpx.Client` module-level, so tests replace its transport with `httpx.MockTransport`.
  - `auth.current_user(request) -> sqlite3.Row` FastAPI dependency: the `users` row with an extra `mealie_token`; raises a redirect to `/login` when there is no valid session. Refreshes the Mealie token when the session is older than 24 hours.
  - Routes: `GET /login`, `POST /login`, `POST /logout`. First sign-in inserts the `users` row with the defaults.
  - App-wide exception handlers: `MealieAuthError` deletes the session and redirects to `/login`; `MealieError` renders `error.html` with status 502 and the text "Can't reach Mealie".
  - `base.html`: bottom tab bar, `{% block content %}`, links to `MEALIE_PUBLIC_URL` for Recipes, Plan and List.
