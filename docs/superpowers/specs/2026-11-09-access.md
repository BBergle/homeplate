# Access: accounts only (revised 2026-11-09)

This replaces the public share page in `2026-11-09-homeplate-design.md`. Decided by the owner after step 2 shipped.

## Decisions made by the owner

- Nothing is public. Only people with an account can see any recipe, photo or user detail.
- A share link is a plain link to the recipe page inside the app. It does not expire. Without an account it leads to the login screen and shows nothing about the recipe.
- Account creation is controlled by one switch that an admin sets in settings. It is off by default and has no timer.
- While the switch is on, the login screen shows "Create account". Using it submits a request; an admin approves or declines each one. No account exists until approval.

## Calls made in design (not each confirmed by the owner)

- The request form collects name, email and an optional note, never a password. Approval creates a single-use Mealie invite; the requester's private status page then leads into the existing join form, and the admin can copy that link to send.
- The admin chooses the household (their own, or a new one) at approval time.
- Limits on the public form: 20 pending requests at most, one pending request per email, identical responses whether or not a limit was hit.
- Invite links an admin creates directly (step 2) stay as the quick path for trusted people.
- Mealie share tokens are no longer used. The signed-in recipe page shows the full recipe (text from Mealie with the viewer's own session) plus everyone's non-private photos.
- After signing in from a recipe link, the user lands on that recipe (a `next` value restricted to recipe paths).

## Out of scope

Email notifications, expiring or revoking invites from Homeplate, rate limiting beyond the caps above.
