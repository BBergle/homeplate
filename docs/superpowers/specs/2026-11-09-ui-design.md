# Homeplate UI design spec

Research depth note: fetches were limited. Tags: [V] = verified from the cited source this session; [M] = from memory, not verified. Contrast ratios were computed with a script (WCAG relative luminance formula), so those are verified.

## Findings

**1. Platform guidance**
- WCAG 2.2 SC 2.5.8 (AA): pointer targets at least 24x24 CSS px, unless spaced or inline. [V] https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html . The app's existing 44px minimum already beats it; keep 44 (Apple's 44pt minimum, [M]).
- Apple HIG tab bars: keep 3-5 tabs, icon plus short label. The page text did not load; claims [M]. https://developer.apple.com/design/human-interface-guidelines/tab-bars
- WCAG text contrast 4.5:1, large text/UI components 3:1 (1.4.3, 1.4.11); focus-visible outline needed (2.4.7; 2.4.11 Focus Not Obscured, which matters for a fixed bottom bar over focused inputs: add scroll-padding-bottom). [M]
- Reduced motion: honour `prefers-reduced-motion`. [M]
- Material 3: 48dp targets, bottom nav 3-5 destinations. [M]

**2. iOS Safari / PWA**
- `viewport-fit=cover` lays the page out to the full screen; you must add `env(safe-area-inset-*)` padding yourself; `env()` works anywhere `var()` does; browsers without it ignore the whole rule, so give fallbacks. [V] https://webkit.org/blog/7929/designing-websites-for-iphone-x/
- Inputs under 16px computed font size trigger focus-zoom on iOS Safari. [M] Current CSS uses `font: inherit` at 16px, fine; keep inputs at exactly 16px or more.
- `apple-mobile-web-app-status-bar-style`: `default`, `black`, `black-translucent` (only the last extends content under the status bar, requires safe-area top padding). [M]
- `theme-color` supports a `media` attribute for per-scheme values. [M]
- `<input type=file accept="image/*">` on iOS offers Photo Library / Take Photo / Choose File; `capture` forces camera and removes library choice, so do not set it. [M]
- `inputmode="decimal"` shows a digit keypad with a decimal point; `numeric` has no point (so calories ok, weights/protein with `step=any` should be decimal). `enterkeyhint="done|next"`. Login: `autocomplete=username` / `current-password`, plus `autocapitalize=none`, `autocorrect=off`, `spellcheck=false` on username. [M]
- `-webkit-tap-highlight-color: transparent` and `overscroll-behavior-y: none` are safe polish; do not disable text selection. [M]

**3. Modern CSS (support)**
- `color-scheme`: Baseline widely available since Jan 2022; styles form controls and scrollbars; add `<meta name="color-scheme">` to stop flash. [V] https://developer.mozilla.org/en-US/docs/Web/CSS/color-scheme
- `light-dark()`: Baseline 2024 (May 2024), takes colours (and images in newer engines); requires `color-scheme: light dark`. Safari 17.5+ [M for versions]. [V for Baseline] https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/light-dark . Decision: use plain `@media (prefers-color-scheme: dark)` token overrides (already in the app, works on every iOS version, zero risk). `light-dark()` is optional.
- `font-variant-numeric: tabular-nums`: Baseline widely available since Jan 2020. [V] https://developer.mozilla.org/en-US/docs/Web/CSS/font-variant-numeric . San Francisco supports it. [M]
- Cross-document view transitions (`@view-transition { navigation: auto; }`): MDN marks it "Limited availability", not Baseline; same-origin only. [V] https://developer.mozilla.org/en-US/docs/Web/CSS/@view-transition . Chrome 126 / Safari 18.2 [M]. Verdict: skip for now. It is harmless progressive enhancement but adds nothing to a retention tool; if wanted later, only a 150ms fade.
- `:has()` (Safari 15.4+), `clamp()`, container queries (Safari 16+), logical properties, `accent-color`, `text-wrap: balance` (Safari 17.5+), `dvh` (Safari 15.4+), `<dialog>`, `<details name>` exclusive accordions (Safari 17.2+, [M]). All [M]; all fine for Safari 17+. Do not rely on `text-wrap: pretty`.

**4. Category patterns** (WebFetch of MacroFactor failed 404; all of this is [M] and should be read as design lore, not citations)
- Daily summary: Apple Fitness uses rings; Cronometer/Lose It use a big remaining-calories number with a bar; MacroFactor leans on plain numbers and trend weight. For a once-or-twice-a-day cooking tool, one ring plus plain numbers beside it works; a ring communicates "fill this" without a pass/fail verdict.
- Fast logging: favourites/recent first, one-tap repeat, optional fields hidden. Entry rows: thumbnail left, name, one muted metadata line, time; delete behind a secondary affordance (details/swipe not available without JS: use a small "Remove" in an overflow `<details>`).
- Streaks: Duolingo shows streak as flame plus count; Streaks app uses a plain ring grid. A weekly (not daily) streak, as Homeplate has, is already forgiving. Show "this week: 2 of 3" as dots, not a bar.
- Recipe reading (Mela, Crouton, Paprika, NYT Cooking): full-bleed hero photo, title large, meta line (time, yield), ingredients before method, ~60-70 character line length, generous line height, no chrome.

**5. Behavioural evidence**
- Red over-limit numbers and rigid streaks are criticised by clinicians and in design write-ups as shame triggers; evidence is mixed and mostly vendor blogs; one therapist account and a 2021 trial note tracking is not uniformly harmful. [V as search result, low authority] https://therapist.com/disorders/eating-disorders/calorie-counting-apps/ , https://www.theswaddle.com/health-tracking-apps-provide-a-worrying-pipeline-to-eating-disorders-better-tech-design-can-fix-that . Treat the recommendation (neutral colour over target, no guilt copy) as a cautious design choice, not proven effect.
- Celebrate once, quietly; never push-nag; "streak" resets to a "fresh start" message. [M, design judgement]

**6. Phone forms** [M]: labels above fields (not placeholders), single column, group with fieldsets, optional fields behind `<details>`, one primary button full width at the form bottom, inline error text tied by `aria-describedby`, `inputmode` keyboards instead of steppers (steppers only for tiny integer ranges like weekly goal).

**7. Dark mode** [M]: avoid pure black; lighter surfaces for higher elevation; desaturate accents; keep muted text at 4.5:1+; dim images slightly (`filter: brightness(.92)`) rather than invert.

**8. Typography** [M]: `system-ui` resolves to San Francisco on iOS; use `ui-rounded` only for big numbers if desired (Safari supports `ui-rounded`; falls back harmlessly). No web fonts needed.

## Design direction

"Warm kitchen notebook": a calm, paper-tinted off-white (dark: warm charcoal), generous spacing, one deep herb-green accent, large friendly numerals in the system rounded face for calories, and food photos as the only decoration. Numbers are neutral: going over target never turns red, it just keeps the ring full and the label says "over by 120". Progress that matters to the behaviour (cooked this week) is the hero of Today and Me, drawn as dots and one ring; achievements and streaks are quiet and forgiving. This suits a non-clinical, family-and-friends audience, avoids diet-app anxiety, and needs only one CSS file, system fonts and inline SVG.

## Component specs

**Tab bar.** Replace the two stacked fixed bars (`.tabs` + `.links`) with one bar of 4 tabs (Today, Me, Order, Ask) with inline-SVG icons (24px, stroke currentColor, 1.75 width) above 12px labels; active tab: accent colour plus a 3px top indicator bar (not colour alone) and `aria-current="page"` set by Jinja from `request.url.path`. Move Recipes/Plan/List to a "Kitchen" card on Today (links to Mealie), since the second fixed bar eats 44px of the screen and competes with the tabs.
```css
.tabs{position:fixed;inset-inline:0;bottom:0;display:flex;background:var(--surface);border-top:1px solid var(--line);padding-bottom:env(safe-area-inset-bottom)}
.tabs a{flex:1;min-height:var(--tab-h);display:flex;flex-direction:column;align-items:center;justify-content:center;gap:2px;font-size:.75rem;font-weight:600;color:var(--muted);text-decoration:none;border-top:3px solid transparent}
.tabs a[aria-current=page]{color:var(--accent);border-top-color:var(--accent)}
main{padding:var(--s-4) var(--s-4) calc(var(--tab-h) + 32px + env(safe-area-inset-bottom))}
```
Muted tab text passes 6:1. Public pages (no sid) render no tab bar (already true).

**Page header.** `<header class="page-head"><h1>Today</h1><p class="muted">Monday 9 Nov</p></header>`; h1 1.75rem, top padding `max(var(--s-4), env(safe-area-inset-top))` only if status bar is black-translucent.

**Card.** `background:var(--surface); border-radius:var(--r-md); padding:var(--s-4); box-shadow:var(--shadow-1); border:1px solid var(--line)` (border kept in dark where shadow is none; dark card is lighter than bg = elevation). Card gap 12px. Entry `<li>`s are not individual cards: one card wrapping a list with hairline separators (less visual noise).

**Stat tile.** Grid of 2: `<div class="stat"><span class="num stat-v">1,240</span><span class="stat-l muted">kcal of 2,000</span></div>`; value in `--font-num` 1.75rem/700, label 0.875rem muted.

**Progress ring (Today hero).** Inline SVG, stroke-dasharray driven by server-computed values; one ring for calories, a slim linear bar for protein. Over target: ring stays full, same accent colour; text "120 over". No red.
```html
<svg class="ring" viewBox="0 0 120 120" role="img" aria-label="1240 of 2000 calories">
  <circle cx="60" cy="60" r="52" fill="none" stroke="var(--surface-2)" stroke-width="12"/>
  <circle cx="60" cy="60" r="52" fill="none" stroke="var(--accent)" stroke-width="12" stroke-linecap="round"
          pathLength="100" stroke-dasharray="{{ [pct,100]|min }} 100" transform="rotate(-90 60 60)"/>
</svg>
```
`pathLength="100"` means Jinja only passes a 0-100 percentage. Ring 112px, centre label via absolutely-positioned `.num` (display size) with "kcal left" or "kcal over" beneath. Track `--surface-2` vs surface is low contrast; fine because the numbers carry the information (ring is redundant). Protein bar: `<div class="bar"><span style="width:62%"></span></div>` can't be inline-style if CSP forbids; use SVG `<rect width="{{pct}}%">` instead, or `<progress>` styled with `accent-color`. Recommend `<progress value max>` with `accent-color: var(--accent)`: native, accessible, zero SVG.

**Entry row.** `<li class="entry"><img class="thumb" ...><div class="grow"><b>Name</b><span class="muted">Cooked, 420 kcal, 32 g</span></div><details class="more"><summary aria-label="More">...</summary><form><button class="btn danger">Remove</button></form></details></li>`. Thumb 56px, radius 10px. Kind shown as a small chip ("Cooked" with a pan icon, "Added" plain), not `strong: ` prefix. Entries with no photo show a 56px `--surface-2` square with an inline SVG plate icon, so rows align. Add `loading="lazy" decoding="async" width/height` on images.

**Buttons.** All 48px high, radius 12px, 600 weight, full width inside forms.
- Primary: bg accent, text on-accent (6.37 / 8.24).
- Secondary: transparent, 1px `--border`, text `--text`.
- Destructive: transparent, text `--danger`, 1px `--border`; confirm via native `<dialog>`/`<details>` ("Remove? Yes / Cancel"); never a one-tap delete right next to content.
- Press state: `:active{transform:scale(.98)}`; disabled `opacity:.5`. Use `hx-disabled-elt="this"` / htmx indicators for in-flight state.

**Form fields.** Label above, 0.875rem/600 `--text` (not muted, current muted label is lower contrast than needed); input 48px, 16px font, bg `--surface`, 1px `--border`, radius 10px; focus: outline accent. Number fields: `inputmode="numeric"` for calories, `decimal` for protein and money; `enterkeyhint="next"` (last field `done`); `autocomplete="off"`. Units as trailing text inside a `.field` wrapper (`<span class="unit">kcal</span>`). Checkbox/radio: keep 24px native with `accent-color: var(--accent)`, whole row 48px tappable (already), put description under in muted.
**Collapsible optional fields.** Native `<details class="more-fields"><summary>Photo, notes and nutrition</summary>...</details>`; summary 48px with chevron via `summary::after` and `details[open]` rotation. Optional fields in "I cooked": recipe (always), then primary button "Log meal"; inside details: photo, leftovers, note, calories, protein. Put the primary button after the details so it is always visible.

**Messages.** `<p class="msg msg-error" role="alert">` bg `--surface-2`, 4px left border `--danger`, text `--text`, icon "!" prefix (not colour alone). Success: `role="status"`, border `--success`, "Logged" with a check icon; htmx can swap it in and it can auto-fade via CSS animation (disabled by reduced motion). Field-level errors: text under the input in `--danger`, `aria-describedby`.

**Achievement badge.** 72px tile grid (3 columns). Earned: filled accent circle, white check/symbol, name bold, caption "Earned" and date. Locked: dashed 2px `--border` circle outline, no fill, lock icon in muted, name muted, caption "Locked" plus the criterion ("Cook 5 times"). Shape (solid vs dashed) and text, not colour, distinguish them. Markup: `<li class="badge earned"><svg aria-hidden>...</svg><span class="badge-name">First cook</span><span class="badge-state">Earned</span></li>`.

**Sparkline.** Keep inline SVG polyline; add: goal-weight dashed horizontal line, final point marked with a circle, last value label as HTML text, `stroke-width 2.5`, `stroke-linecap/linejoin round`, `vector-effect: non-scaling-stroke`, a faint area fill with `--accent` at 12% opacity (`fill-opacity`). Show trend, not daily jitter: label "Last 90 days". Aria-label states start and end values.

**Photo grid (gallery).** `display:grid; grid-template-columns:repeat(auto-fill,minmax(110px,1fr)); gap:4px; border-radius:var(--r-md); overflow:hidden`. Each `<a><img aspect-ratio:1 object-fit:cover loading=lazy></a>`; first photo may span 2x2 (`grid-column:span 2;grid-row:span 2`). Tapping opens a native `<dialog>` lightbox or just the full-size image URL (no JS: use `:target` or a plain link). Caption: cook's first name, date. Upload-tile at the start: dashed square with plus icon.

**Public share page.** No tab bar, no auth chrome. Order: hero photo full-bleed (aspect-ratio 4/3, `max-height:50dvh`, object-fit cover) -> h1 title (balance) -> meta chips (time, servings) -> "Cooked N times by the family" + photo strip (horizontal scroll with `scroll-snap-type:x mandatory`) -> Ingredients card -> Method as numbered steps (`ol`, 1.0625rem/1.6, max-width 65ch, each step with big number) -> "Everyone's photos" grid -> small footer "Shared from Homeplate" (no sign-up pressure; optional "Join" link only if the share was an invite). Set `<meta property="og:title|og:image|og:description">` and `og:image` to the hero (Messages previews use these [M]). Must work with the same CSS file and both colour schemes. Add `@media print` simple styles optional.

**Empty states.** Card with 40px line icon in muted, one-line h2 ("Nothing logged yet"), one muted sentence ("Log what you cooked and it will show up here."), and the primary action button. Never a blank list. Me: no weight yet -> "Add your first weigh-in" link to Today weight card.

**Login.** Centered column, max-width 360px, vertical padding top 12dvh; wordmark "homeplate" with plate icon (SVG), one-line tagline ("Cook at home. Keep the change."), card with two fields and full-width primary "Sign in", error message above the button using `.msg-error`. Attributes: `autocomplete="username"`, `autocapitalize="none"`, `autocorrect="off"`, `spellcheck="false"`, `enterkeyhint="next"`; password `autocomplete="current-password"` `enterkeyhint="go"`. Helper text: "Use your Mealie account."

## Do not do

- Red or warning colour on calorie/protein numbers when over target; "You exceeded", "Failed", "Cheat" copy.
- Daily streak with loss language ("You lost your 12-day streak"); keep weekly and say "fresh start".
- Push-style nagging banners, confetti loops, or autoplay animation; one quiet check mark on first cook of the week is enough.
- Anything needing a build step: Sass, Tailwind, icon fonts from npm, chart libraries; web fonts from Google; inline `<script>`.
- Pure `#000` dark background or pure `#fff` text; saturated green accent on dark.
- Placeholders as labels; `capture` on the photo input; `maximum-scale=1` / `user-scalable=no` in the viewport (blocks zoom, fails accessibility).
- Cross-document view transitions or `text-wrap: pretty` as load-bearing (not Baseline); animate only opacity/transform.
- Emoji as icons for state (inconsistent rendering, not accessible); status conveyed by colour alone.
- One-tap Delete beside every entry; two fixed bars at the bottom.
- Number steppers for calories/weight (use the keypad); showing every field of "I cooked" at once.
